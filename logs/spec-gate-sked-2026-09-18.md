## 2. Рішення, прийняті людиною

| Рішення | Обґрунтування |
|---|---|
| Один користувач — один акаунт (1:1) | Спрощення моделі для v1 |
| Роль адміністратора відсутня; кожен бачить лише власні записи | Мінімалізм і приватність |
| Обов'язкові поля: назва вправи, кількість хвилин, дата | Достатньо для базового обліку |
| Дата виконання не може бути в майбутньому | Запис фіксує вже виконану вправу |
| Тривалість — додатне ціле число хвилин, > 0 | Нульове тренування не має сенсу |
| Записи користувача видаляються разом із його акаунтом | Мінімалізм; історія не потрібна після видалення |
| Експорт у файл — out of scope | Не входить до базової версії |
| Аналітика та графіки — out of scope | Не входить до базової версії |
| Користувач бачить виключно власні записи | Ізоляція даних як базова вимога |
| Пошук за назвою вправи — обов'язковий | Основний сценарій використання |
| Редагування власного запису дозволено | Потреба виправляти помилки вводу |
| Підтвердження при видаленні — обов'язкове | Захист від випадкового видалення |
| Нотатки до запису — опціональні | Додаткова інформація, не обов'язкова |

## 3. Припущення моделі, виправлені або відхилені людиною

| Припущення моделі | Статус | Коментар |
|---|---|---|
| Наявність ролі адміністратора з доступом до всіх записів | Відхилено | Плоска модель: лише звичайний користувач |
| Можливість публічного профілю та рейтингів | Відхилено | Out of scope |
| Інтеграція з фітнес-трекерами | Відхилено | Out of scope |
| Експорт даних у CSV/JSON | Відхилено | Out of scope для v1 |
| Побудова графіків прогресу | Відхилено | Out of scope для v1 |
| Можливість запису дати в майбутньому | Відхилено | Лише минуле або поточна дата |
| Дозвіл нульової тривалості | Відхилено | Тривалість > 0 |
| Спільний доступ до записів між користувачами | Відхилено | Ізоляція даних обов'язкова |
